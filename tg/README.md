# KK — передзамовлення через Telegram

Прототип: https://andreyfedorovskiy.github.io/kk-design/tg/ (демо-залишки, замовлення нікуди не відправляється).

## Як це працює

1. Клієнт пише боту `/start` (або переходить за посиланням `t.me/<бот>?start=kyiv-1` з QR-коду в магазині) і натискає «Наявність і передзамовлення».
2. Відкривається міні-застосунок (`index.html`) усередині Telegram: обирає магазин → бачить залишки саме там → відкладає товар → обирає день/час → підтверджує.
3. Замовлення падає в Telegram-групу цього магазину з кнопками «Підтвердити / Зібрано / Скасувати», залишок у таблиці зменшується, запис іде в аркуш «Замовлення».
4. Клієнту бот надсилає статуси («підтверджено», «зібрано, чекаємо на вас»).

Все безкоштовно: Telegram Bot API, GitHub Pages (міні-застосунок), Google Таблиця + Apps Script (дані й бот).

## Запуск (≈30 хв)

1. @BotFather → `/newbot` → отримати токен.
2. Створити Google Таблицю з аркушами `Магазини`, `Товари`, `Залишки` (заголовки — у верхній частині `bot/Code.gs`). Вміст `demo-data.json` можна взяти як приклад.
3. Розширення → Apps Script → вставити `bot/Code.gs`. У Script properties додати `BOT_TOKEN` і `WEBAPP_URL`.
4. Deploy → New deployment → Web app, Execute as: Me, Access: Anyone. Скопіювати URL.
5. Запустити функцію `setWebhook` один раз.
6. В `index.html` у `CONFIG` вказати цей URL у `DATA_URL` і `ORDER_URL`.
7. Додати бота в Telegram-групу кожного магазину, дізнатися `chat_id` групи і вписати в аркуш `Магазини`.
8. (Опційно) Тригер за часом на `expireReservations` — щогодини.

## Звідки беруться залишки

Найпростіше — продавці чи склад оновлюють аркуш `Залишки`. Якщо облік у 1С/BAS, Poster, KeyCRM тощо — налаштовується автоматичне вивантаження в цю таблицю (або бот читатиме їх API напряму), міні-застосунок при цьому не змінюється.
